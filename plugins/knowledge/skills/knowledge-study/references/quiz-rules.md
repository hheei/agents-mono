# Quiz and comprehension-check rules

These rules are adapted from `bevibing/tutor-skills` without its Obsidian dashboard or persistent tracking.

## No-answer-leakage rule

Questions must test understanding without signaling the answer.

- Keep option labels and descriptions neutral.
- Do not mark an option as recommended.
- Vary the position of correct options.
- Use plausible distractors based on common misconceptions from the chapter.
- Ask about meaning, behavior, assumptions, limits, or consequences rather than echoing a sentence from the notes.

## Useful check types

- Conceptual explanation: “Why is this assumption needed?”
- Prediction: “What changes if this parameter doubles?”
- Distinction: “Which step is a definition and which is derived?”
- Derivation step: “What follows from this line, and why?”
- Dimensional or limiting-case check.
- Small application using the chapter's example pattern.

Prefer one focused question after one concept. Use a multi-question quiz only when the learner requests review or when checking chapter integration.

## Difficulty

Start with the concept just taught, then vary representation or context. Hard questions should require connecting steps, not obscure trivia. Test only material already taught unless the question is explicitly diagnostic.

## Hint-first correction

When an answer is wrong:

1. Find the first incorrect step.
2. Preserve everything before it that was correct.
3. Point toward the relevant definition, assumption, equation, or limiting case.
4. Ask the learner to retry from that step.

Do not repeat the same question verbatim after an error. Rephrase or reduce it to a smaller subproblem. Do not give the complete answer unless the learner asks or chooses it after hints.

## Source discipline

Base checks on the loaded chapter and its prerequisites. If a question uses knowledge not present in the course, label it `Supplementary` before asking it.
